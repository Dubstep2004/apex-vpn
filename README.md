## 🚀 Установка — пошагово

> Шаги 1–3 делаются **один раз**. Потом для каждой новой версии — только шаги 4–6 (или включите автопубликацию, и сервер будет делать их сам).

| | Шаг | Где | Время |
|:-:|---|---|---|
| 1 | Установить сервер | VPS | 5 мин |
| 2 | Добавить адрес сервера | GitHub | 1 мин |
| 3 | Добавить ключ подписи | VPS + GitHub | 2 мин |
| 4 | Запустить сборку | GitHub | ~25 мин |
| 5 | Проверить Releases | GitHub | — |
| 6 | Выпустить версию | VPS | 1 мин |
| 7 | Установить на телефон | Телефон | 1 мин |

**Что нужно заранее:** VPS на Ubuntu или Debian, домен (например `vpn.ваш-домен.ru`) с A-записью на IP этого VPS, доступ к серверу по SSH под root.

### 1️⃣ Установите сервер на VPS

<img src="docs/guide/step1.webp" width="100%">

Подключитесь к VPS по SSH и выполните:

```bash
curl -fsSL -o apex https://raw.githubusercontent.com/Dubstep2004/apex-vpn/main/server/apex && sudo bash apex
```

В меню нажмите **1**, введите домен. Через пару минут скрипт напечатает адрес сервера, например:

```
https://vpn.ваш-домен.ru/apexvpn
```

**Скопируйте его** — он нужен на шаге 2.

> [!TIP]
> Если репозиторий приватный, ссылка `raw.githubusercontent.com` не откроется. Скопируйте папку `server/` на VPS (например, через `scp -r server root@IP:/root/`) и запустите `sudo bash /root/server/install.sh vpn.ваш-домен.ru`.
>
> Если порт 443 уже занят VPN-сервером, сайт поднимется на порту 8443 — адрес будет с `:8443`.

### 2️⃣ Добавьте адрес сервера в GitHub

<img src="docs/guide/step2.webp" width="100%">

1. Откройте репозиторий на GitHub → **Settings**.
2. Слева: **Secrets and variables** → **Actions**.
3. Вкладка **Variables** → кнопка **New repository variable**.
4. Заполните и нажмите **Add variable**:

| Name | Value |
|---|---|
| `SERVER_URL` | адрес из шага 1, например `https://vpn.ваш-домен.ru/apexvpn` |

### 3️⃣ Добавьте ключ подписи (один раз)

<img src="docs/guide/step3.webp" width="100%">

На VPS выполните `sudo apex` и выберите пункт **22 «Ключ подписи для GitHub»**. Скрипт покажет два значения.

В GitHub: **Settings → Secrets and variables → Actions → вкладка Secrets → New repository secret**. Добавьте два секрета:

| Name | Secret |
|---|---|
| `APEX_KEYSTORE_PASSWORD` | строка после `Value:` |
| `APEX_KEYSTORE_BASE64` | длинная строка — **целиком**, без пробелов и переносов |

> [!IMPORTANT]
> Без этого шага версии с GitHub и с сервера подписаны разными ключами, и телефон пишет **«Приложение не установлено, так как оно конфликтует с другим пакетом»**. Ключ подписи никому не отправляйте — только в секреты GitHub.

### 4️⃣ Запустите сборку

<img src="docs/guide/step4.webp" width="100%">

**Actions** → слева **Build APEX VPN** → справа **Run workflow** → зелёная кнопка **Run workflow**.

Сборка идёт около 25 минут. Зелёная галочка — готово, красный крестик — ошибка (откройте сборку и посмотрите, что написано в красном блоке).

### 5️⃣ Проверьте Releases

<img src="docs/guide/step5.webp" width="100%">

Справа на главной странице репозитория — **Releases**. Там появится новая версия с файлом `apex-vpn-<версия>.apk`. Запомните номер версии (например, `1.7.1`).

### 6️⃣ Выпустите версию со своего сервера

<img src="docs/guide/step6.webp" width="100%">

```bash
sudo apex publish 1.7.1
```

Или `sudo apex` → пункт **2**. Сервер скачает APK с GitHub, подпишет своим ключом и выложит для всех.

> [!TIP]
> Чтобы не делать это руками: `sudo apex` → пункт **17 «Автопубликация»**. Сервер будет каждые 30 минут проверять GitHub и сам выпускать новые версии.

### 7️⃣ Установите на телефон

<img src="docs/guide/step7.webp" width="100%">

1. **Один раз** удалите старую версию APEX VPN: Настройки → Приложения → APEX VPN → Удалить.
2. Откройте на телефоне `https://vpn.ваш-домен.ru/apexvpn/` → **Скачать APK**.
3. Установите. Если телефон спросит — разрешите установку из браузера.
4. Вставьте ссылку подписки (или отсканируйте QR-код).

Дальше всё само: при выходе новой версии приложение скачает её и откроет установщик.

### ❓ Если что-то не так

| Проблема | Что делать |
|---|---|
| «Конфликтует с другим пакетом» | Удалите APEX VPN один раз и поставьте заново. Проверьте, что сделан шаг 3. |
| Приложение не видит обновлений | Проверьте `SERVER_URL` (шаг 2) и что версия выпущена (`sudo apex` → пункт 9). |
| Сертификат не выдаётся | Домен должен указывать на IP сервера, порт 80 должен быть открыт. `sudo apex` → пункт 12. |
| Сборка на GitHub красная | Откройте сборку в **Actions** — ошибка написана в красном блоке **Annotations**. |
| Нужна помощь пользователю | В приложении: **Настройки → Написать в поддержку** — отчёт с журналом одной кнопкой. |

Все команды сервера — в **[server/README.md](server/README.md)**.

## 🛠️ Сборка

Обычная сборка — через GitHub Actions, см. **[🚀 Установка — пошагово](#-установка--пошагово)**.

<details>
<summary><b>Локально</b></summary>

Нужны JDK 17, Go 1.25+, Android SDK и NDK `28.0.13004108`.

```bash
export ANDROID_HOME=~/Android/Sdk
./core/build-core.sh                      # ядро → app/libs/libbox.aar
./core/fetch-xray.sh                      # Xray → jniLibs
./gradlew assembleRelease
```

</details>

<details>
<summary><b>Структура проекта</b></summary>

```
app/                    Android-приложение (Kotlin, Jetpack Compose)
  …/vpn/                VpnService, ядра sing-box и Xray, виджеты, ярлыки
  …/data/               подписка, настройки, пинг, звуки, обновление баз
  …/update/             обновление приложения
  …/ui/                 экраны, темы, карта
wear/                   приложение для часов Wear OS
core/apexcore/          Go: разбор подписки → конфиги sing-box и Xray (+ тесты)
server/                 сервер обновлений для VPS (install.sh, меню apex)
.github/workflows/      сборка APK
```

</details>

<details>
<summary><b>Как выпустить обновление</b></summary>

1. В `app/build.gradle.kts` увеличьте `versionCode` и `versionName`, добавьте запись в `data/Changelog.kt`.
2. Дождитесь сборки на GitHub.
3. На сервере выполните `apex publish <версия>` (с `--mandatory` обновление станет обязательным).
4. Пользователи увидят обновление при следующем запуске. По Wi-Fi файл скачивается заранее, а установщик открывается сам.

| поле `update.json` | смысл |
|---|---|
| `versionCode` | номер сборки; обновление показывается, если он больше установленного |
| `versionName` | версия для пользователя |
| `apkUrl` | прямая https-ссылка на APK |
| `sha256` | контрольная сумма APK |
| `changelog` | что нового |
| `mandatory` | `true`: обновление нельзя отложить |
| `minSupportedVersionCode` | версии ниже этого номера обязаны обновиться |

</details>

<details>
<summary><b>Подписка и Remnawave</b></summary>

- Приложение понимает base64-список ссылок, обычный список и JSON sing-box.
- Заголовки ответа: `profile-title`, `announce`, `support-url`, `profile-web-page-url`, `subscription-userinfo`, `profile-update-interval`. Их можно передать и строками `#имя: значение` в теле подписки.
- User-Agent: `APEX VPN/<версия>`.
- Remnawave отдаёт «Описание сервера» только Happ и INCY. Чтобы его видел APEX, добавьте правило ответа (Response Rule) с `additionalExtendedClientsRegex: ["^APEX VPN/"]`.

</details>

<details>
<summary><b>Отчёты о сбоях и приватность</b></summary>

Приложение отправляет на ваш сервер текст ошибки, модель телефона и версию Android. Ссылка подписки, IP и списки сайтов в отчёт не попадают. Отправку можно отключить в настройках. Посмотреть отчёты на сервере: `apex crashes`.

</details>
